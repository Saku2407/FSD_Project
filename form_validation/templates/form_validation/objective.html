Objective

Learning objectives

After completing this experiment, you will be able to:

  1. Explain why built-in field validation is not enough for real-world forms.
  2. Describe the order in which Django runs field validation, clean_<fieldname>() and clean().
  3. Write a clean_<fieldname>() method that validates a single field and returns the cleaned value.
  4. Write a clean() method that validates relationships between fields, such as matching passwords.
  5. Raise ValidationError with clear, user-friendly messages and error codes.
  6. Attach errors to a specific field using add_error(), or create a non-field error using add_error(None, ...).
  7. Display field errors and non-field errors correctly in a Django template.

Prerequisites

  • Basic Python (functions, classes, exceptions)
  • Django project structure (apps, views, URLs, templates)
  • Basics of HTML forms and the GET and POST methods

What you will do

  • Read the Theory with code examples
  • Submit valid and invalid data in the Experiment
  • Check your understanding in the Assessment
  • Share your thoughts in Feedback
