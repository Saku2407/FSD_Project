What is a migration?

A migration is a Python file that describes one change to your database schema: create a table, add a column, rename a field, and so on. Migrations are Django's version control for the database. They live in each app's migrations/ folder and are numbered in order: 0001_initial.py, 0002_book_published.py, ...

The workflow

Edit models.py→ makemigrations→ New migration file→ migrate→ Database updated
  1. makemigrations compares your current models with the state described by the existing migration files. If they differ, it writes a new migration file. It does not touch the database.
  2. migrate finds the migrations that have not been applied yet, runs them against the database, and records each one in the django_migrations table.

Anatomy of a migration file

from django.db import migrations, models


class Migration(migrations.Migration):

    initial = True

    dependencies = []

    operations = [
        migrations.CreateModel(
            name='Book',
            fields=[
                ('id', models.BigAutoField(auto_created=True, primary_key=True,
                                           serialize=False, verbose_name='ID')),
                ('title', models.CharField(max_length=100)),
                ('pages', models.IntegerField()),
            ],
        ),
    ]
  • dependencies: migrations that must be applied before this one. The first migration has none; later ones list the previous migration, for example ('library', '0001_initial').
  • operations: the list of changes, each an object such as CreateModel or AddField. Django converts them to SQL for your particular database.

Commands you will use

CommandWhat it does
python manage.py makemigrations [app]Creates migration files from model changes. Add --dry-run to preview.
python manage.py migrate [app]Applies unapplied migrations to the database.
python manage.py showmigrations [app]Lists migrations; [X] means applied, [ ] means not yet.
python manage.py sqlmigrate app 0001Prints the SQL of a migration without running it.

The django_migrations table

Django stores one row per applied migration (the app, the migration name and the time it was applied) in a table named django_migrations. When you run migrate, Django compares the migration files on disk with these rows and runs only what is missing. That is why running migrate twice is safe, and why running makemigrations with no model changes simply says No changes detected.

Good habits

  • Commit migration files to version control so teammates and servers build the same schema.
  • Do not edit a migration that has already been applied elsewhere. Create a new one instead.
  • Read the generated file (and the output of sqlmigrate) before applying it to important data.
