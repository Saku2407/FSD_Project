From class to table

Django includes an ORM (object-relational mapper). You describe your data as a Python class that inherits from django.db.models.Model. Django maps that class to a database table, every attribute to a column, and every instance to a row.

from django.db import models

class Book(models.Model):
    title = models.CharField(max_length=100)
    pages = models.IntegerField()
    published = models.DateField(null=True, blank=True)

    def __str__(self):
        return self.title

For an app named library, this class is stored in a table called library_book: the app label, an underscore, and the lower-case model name. You can override this with Meta.db_table.

Primary key

If you do not declare a primary key, Django adds an auto-incrementing id column for you. To use a different primary key, set primary_key=True on one field.

Field options

OptionMeaning
null=TrueThe database column may store NULL.
blank=TrueForms and the admin accept an empty value (validation only).
default=...Value used when none is given. It is applied by Django in Python, not stored as a database default.
unique=TrueNo two rows may have the same value (adds a UNIQUE constraint).
choices=...Restricts the value to a fixed list.
auto_now_add=TrueSets a date/time field once, when the row is created.

Convention: for text fields such as CharField, prefer blank=True and store an empty string rather than null=True. Otherwise "no value" has two representations, NULL and ''.

Relationships

A ForeignKey creates a many-to-one relationship: many books can point to one author.

class Book(models.Model):
    author = models.ForeignKey(Author, on_delete=models.CASCADE)
  • The column is named after the field plus _id, so here it is author_id.
  • on_delete is required. It decides what happens to the book when its author is deleted: CASCADE deletes the book too, PROTECT refuses the deletion, SET_NULL sets the column to NULL (needs null=True).
  • ManyToManyField and OneToOneField cover the other relationship types.

Meta options and __str__

An inner class Meta holds model-level settings such as ordering, db_table and constraints. Defining __str__ makes objects readable in the admin and in the shell.

Important: writing or changing a model does not touch the database. The database changes only after you create and apply a migration, which is the subject of Experiment 2.
