Understanding Git Repository Management

Git is a distributed version control system. It tracks versions of files so you can experiment, review and collaborate safely.

Three areas of a Git project

01Working treeEdit files
→
02Staging areagit add
→
03Local repositorygit commit

The working tree contains files on disk. git add stages a snapshot, and git commit saves the staged snapshot as a new commit. Later changes to a staged file require staging again.

Core commands

CommandPurpose
git initCreate a repository inside the current Django project directory
git statusShow staged, modified and untracked files
git add README.mdStage the current contents of README.md
git commit -m "Initial commit"Create a commit from staged files
git log --onelineInspect commit history
git branch featureCreate a new branch at the current commit
git switch featureSwitch to that existing branch
git merge featureMerge feature into the currently checked-out branch
git remote add origin URLConfigure a remote repository address
git push -u origin mainPublish local commits to a configured remote

Commit source code and dependency descriptions; normally exclude .venv/, __pycache__/, secrets, and local development database files using .gitignore.

Branches and fast-forward merging

A branch is a movable name for a commit. When a feature branch moves ahead of main and main has not changed independently, git merge feature can advance main without creating another merge commit (fast-forward).

Simulation scope: This lab models local Git concepts in your browser session. It does not execute Git, clone repositories, run Django code or connect to GitHub. Remote operations and conflict resolution are covered in the references and manual practice notes.
